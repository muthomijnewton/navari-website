A little know-how goes a long way.

Use this workflow when goods are being sold now. For an order to fulfil later, use Sales Orders. Restaurant staff should use Take Dine-in and Takeaway Orders.

Before you start

Sign in with your own user, open your POS shift and confirm the counter/profile. Prices, warehouse stock and payment methods depend on that profile. You need a connection to the server to finish checkout.

Make the sale

  1. Confirm the customer above the cart, or choose the correct customer. A named customer may have different prices or loyalty points.
  2. Select a shipping address below the customer when needed. Only addresses you may access are offered.
  3. Search for an item by name, code or barcode, or use the scanner. Choose a variant if the item has options.
  4. Review quantity and selling UOM on the cart line. Expand the line to change UOM, add a note or review batch/serial allocation.
  5. Check the selected price list, discounts you are allowed to enter, subtotal, taxes and grand total.
  6. Select Checkout. Enter any required checkout fields, delivery amount or walk-in Tax ID.
  7. Allocate the payable amount to the configured payment methods. If using an integrated gateway, wait for payment verification.
  8. Review the final total and select the completion action shown. Do not treat an opened checkout dialog as a completed sale.
  9. Confirm the result and invoice number. Print the receipt if needed.

An enabled approval workflow may save the transaction for approval instead of submitting it. Follow the available workflow action explicitly; see Checkout Fields and Approval Workflows.

If you need to pause

Use Hold to save an unfinished invoice. Find it under Sales History → Draft Invoices. Clearing the cart or refreshing an unsaved page is not the same as holding it.

On small screens the checkout footer shows Hold and Complete; some desktop actions are not shown there.

If checkout does not finish

Read the message before trying again. Correct stock/allocation problems or check a pending payment. If the result is unclear, check Sales History or the submission panel before starting another sale. Never collect a second payment merely because the first response was delayed.
