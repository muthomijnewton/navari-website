A little know-how goes a long way.

Use kitchen routing for items that must be prepared after an order is placed. A ready-to-sell bottled drink can remain direct-sale stock; a prepared dish needs a recipe and production setup.

Decide which items need preparation

Kitchen Stations claim ERPNext Item Groups, including descendants. If an item's group matches an eligible station, it is treated as a prepared/QSR item. The catalogue identifies preparation items with a QSR label.

An item not mapped to a kitchen can remain a direct-sale item. Do not map the entire item tree to a kitchen unless every matching sale item should need production.

Menu Sections/Courses organize the menu; they do not route preparation.

Prepare the recipe and stock

Enable Stock Reservation in Stock Settings before placing stock-bearing
restaurant orders. This protects promised ingredients/output from being sold to
another order while preparation is in progress.

For each routed main item:

  1. Configure it as a stock Item.
  2. Create an active, submitted default ERPNext BOM for the profile Company.
  3. Use valid ingredient UOMs and quantities.
  4. Put ingredients in the station's raw-material warehouse.
  5. Confirm finished goods will be sold from the POS Profile warehouse.

Optional work-in-progress configuration supports the required transfer/manufacture steps. Standard ERPNext tracking, quality-inspection, manufacturing and whole-number UOM rules still apply.

An ingredient quantity of 0.4 Nos is invalid when Nos must be whole. Fix the recipe or ingredient UOM; do not turn off stock validation to make the menu orderable.

Create the stations

In Kitchen Station, select its name, Company, Restaurant and Branch. Add the Item Groups it prepares and its preparation warehouses.

Use narrower groups for a specialist station. If Tea is mapped to one station and its Coffee child group to another, the closest matching child mapping wins. Two enabled shared stations cannot both claim the same exact group in one Restaurant/Branch.

Route by floor when needed

Leave Floor-wise Station off for a shared station, including takeaway. Enable it and select one or more matching floors for a local kitchen.

For the same Item Group, a matching floor-specific station takes priority over the shared station. Disjoint floor stations may reuse a group. Overlapping floor stations cannot compete for the same exact group.

Example: Main Kitchen is shared for Prepared Food, while Terrace Kitchen handles that same group on Terrace. Takeaway uses the shared station.

Group specificity is resolved before the floor-specific tie-break. A more-specific shared Coffee mapping can therefore beat a floor station mapped only to a broader Drinks group.

[Diagram: Table floor + most-specific Item Group → eligible floor station or shared fallback → ingredient warehouse → finished-goods warehouse]

What placement does

The POS checks recipe ingredients when the prepared item is ordered. Placing the round creates station KOTs, native Work Orders and stock reservations. Preparation manufactures the output; invoicing consumes the sold stock.

An item configured for preparation only on another floor does not silently become a direct-sale item. Fix its routing or choose a permitted temporary station when the prompt offers one. A hidden preferred station is not bypassed by falling back to a visible shared station.

Add-ons follow their prepared parent's routing. Review their stock setup too: a priced extra is still a real Item.

Test before opening

Place one dish from each mapped group, check its KDS destination and complete production. Repeat for each floor and for takeaway. Test an ingredient shortage and confirm staff receive a useful error before placing the order.
