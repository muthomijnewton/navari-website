A little know-how goes a long way.

Use menus to decide what staff can order and how they browse it. Keep selling prices in ERPNext Item Price/Pricing Rules rather than treating the menu as another price list.

Organize the menu

  1. Create enabled Menu Sections, such as Breakfast, Main Dishes and Drinks. Display Order controls their browsing order.
  2. Create the required Items, UOMs and selling prices.
  3. Open Restaurant Menu, enter its name and choose any Company/Restaurant scope needed.
  4. Add each Item or variant template under Items and select its Section/Course.
  5. Leave Available enabled for orderable items; clear it to stop ordering that menu item temporarily.
  6. Enable/save the menu and assign the shared default on Restaurant if required.

The same item should appear once in the menu. Choose the actual variant when ordering from a template. A Section/Course is not a kitchen destination or an automatic instruction to fire a course later.

Shared, branch and floor menus

  • Default: select the shared menu as Restaurant's Default Menu.
  • Branch-specific: select Restaurant and Branch on the menu. Only one enabled branch-wide menu can apply to that pair.
  • Floor-specific: enable Floor-wise Menu and add the floors it serves. Any chosen Company, Restaurant or Branch must match those floors. A floor cannot have two competing enabled floor menus.

For dine-in the application prefers the floor menu, then the branch-wide menu, then Restaurant default. If no menu applies, the profile's permitted Item Groups can be the fallback. Configure an explicit menu when the list must be restricted.

Selecting the table first is therefore important: it determines which floor's menu applies. A takeaway visit has no table/floor and uses the applicable non-floor menu.

[Screenshot: Restaurant Menu showing Restaurant, Branch, Floor-wise Menu, floor assignments and Items with Section/Course and Available]

Set service-specific prices or charges

A service type may have its own selling Price List and Sales Taxes and Charges Template. The list must be enabled, selling and in the profile currency; the tax template must belong to the profile Company.

Only items priced in that service's list are offered for that service. Use this when takeaway prices differ or dine-in has a configured service charge. Leaving the service overrides empty uses the normal pricing/tax defaults.

Test a real cart after configuration. A delivery amount is not automatically created merely because the service is named Delivery.

Configure modifiers and add-ons on Item

Use the Item's Restaurant tab, not repeated menu assignments:

  • Modifier Groups are reusable choices, such as preparation preference. Configure the choices and minimum/maximum selections on Restaurant Modifier Group.
  • An optional choice can have no charge. A chargeable modifier can link an Add-on Item.
  • Optional Add-ons link real sales Items with a quantity/UOM per main selling unit. Their price/tax comes from the transaction's selling setup.

For example, an omelette can offer required egg preparation plus optional cheese. Add-ons are separate priced order lines linked to the main item; they are not a hidden rate adjustment.

Variants inherit the template's restaurant options unless configured on the variant or Override Template Restaurant Options is enabled. An explicit override with empty tables can intentionally suppress inherited choices.

Keep a simple note for an exceptional request, but do not use notes instead of required priced choices. Changes to the master later do not rewrite the choice snapshot of a placed round.
