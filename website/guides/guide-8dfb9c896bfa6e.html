A little know-how goes a long way.

Use this guide to prepare a new restaurant location. Start with a small working menu and test waiter, chef and cashier accounts before loading the full operation.

1. Prepare the company and stock locations

Complete the standard counter setup: Company, accounts, tax templates, selling price list, payment accounts and a default customer.

Choose the warehouse from which completed dishes and direct-sale products will be sold. Configure raw-material and optional work-in-progress warehouses for the kitchens. These must belong to the same Company.

Enable Stock Reservation in Stock Settings for stock-bearing restaurant orders.
Have stock/manufacturing staff prepare real recipes and ingredient balances
before the first service.

2. Identify the restaurant and branch

Create/select the ERPNext Branch and set its Company. Create Restaurant with its name, Company and enabled status.

Restaurant and Branch are independent records. A Restaurant can operate across several branches of its Company; a branch is not owned by a single Restaurant record. Operational records pair the two. Use that same Restaurant/Branch pair on profiles, floors and kitchen stations.

Leave Default Menu blank until the menu exists, then return and select it. You do not need a second Restaurant named after every floor.

3. Decide which services you offer

Configure Restaurant Service Type for Dine In, Takeaway or your business's equivalent labels:

  • Enable Requires Table for dine-in.
  • Leave it off for table-free service.
  • Use Display Order to control the selection order.
  • Add a service-specific Price List or tax template only when it should override the normal transaction pricing.

In Restaurant → Service Types, add rows in the order Service Type, Branch, Default:

  • Leave Branch blank for services offered by branches without their own list.
  • To give a branch its own list, select that Branch on every service it should offer.
    This list replaces the blank-Branch rows for that branch; it does not add to them.
  • Select one Default per branch, and one for the blank-Branch list. If none is
    selected, the first enabled service in Display Order is selected automatically.
  • You can repeat a service for different branches, but not twice for the same
    branch or twice with Branch blank. Branch must belong to the Restaurant's Company.

For example, offer Dine In and Takeaway with Branch blank, then add only Takeaway
for Meru. Meru offers Takeaway only; Nairobi uses Dine In and Takeaway unless it
has its own rows. Every POS Profile with the same Restaurant/Branch uses that list.

Disabled service types are never offered. If a branch's list contains only disabled
services, it does not fall back to the shared list. A branch without its own rows
or blank-Branch rows has no offered services once the Restaurant has service
assignments. If the entire Service Types table is empty, all enabled service types
remain available; configure explicit rows to restrict them.

Avoid offering a label that staff cannot actually fulfil. A service named Delivery
is a table-free ordering choice, not a delivery-management system.

[Screenshot: Restaurant Service Types showing blank-Branch Dine In and Takeaway rows, a Meru Takeaway row, and defaults for each scope]

4. Prepare items, prices and a menu

Create sales Items and Item Prices. Configure Menu Section records, then Restaurant Menu items with a Section/Course and availability.

Select the menu as the Restaurant's default. For branch/floor menus, follow Build Menus and Item Choices. Menu sections organize selling; Item Groups route kitchen work.

5. Configure the restaurant counter

In POS Profile:

  1. Set POS Mode to Restaurant.
  2. Select Restaurant and Restaurant Branch, matching the profile Company.
  3. Confirm the selling warehouse, currency, selling price list, customer, taxes and payment accounts.
  4. Add each operating user under the profile's user assignments.
  5. Enable only the customer/payment and approval options the counter needs.

Company, warehouse and accounting defaults stay on the profile; do not recreate them as separate outlet settings.

A profile with restaurant transaction history cannot simply be moved to another Restaurant/Branch. Create another profile for a different operating location.

6. Arrange tables and kitchens

After the profile exists, managers can use Floor → Floor Editor to build the plan. Floors and tables can also be maintained in Desk; floors are paired to Restaurant/Branch and tables inherit them.

Then complete Configure Kitchen Preparation, including recipes and ingredient stock. Apply floor-specific menus/stations after the floors exist.

[Diagram: Company → Restaurant and Branch context; Items/Prices → Menu; POS Profile → Floor Editor; Floors + Item Groups + preparation warehouses → Kitchen Stations]

7. Assign staff roles and access

Role Use it for
VunaPOS Restaurant Manager Restaurant setup and management actions.
VunaPOS Waiter Guest visits, ordering and serving.
VunaPOS Kitchen User KDS preparation actions.
VunaPOS Cashier Billing and collecting restaurant payments.

Users may hold more than one role when your business needs it. Kitchen-only users open directly into kitchen functions and need no selling shift. Waiters and cashiers open separate shifts even on the same profile.

Assign the relevant profile and standard permissions. Optional Branch and Kitchen Station User Permissions restrict records further; they are not mandatory for every installation. Do not grant accounting/manufacturing administration to every chef just to use KDS.

8. Rehearse a visit

On separate browser profiles/devices: waiter opens a shift and places an order; chef opens KDS and prepares it; cashier opens their own shift and bills the same visit. Confirm prices, stock movements, receipt and table release.
