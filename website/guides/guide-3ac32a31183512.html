A little know-how goes a long way.

Use this guide when the terminal disconnects, a payment stays pending or checkout returns an unclear result.

Connection loss is not offline checkout

The terminal caches catalogue information to reduce loading and may still show items after a connection problem. That is not permission to complete financial transactions offline. Checkout, payments and restaurant order placement need the server.

Reconnect and sign in again if your session expired. If the server returns a login/error page instead of a normal response, do not treat that as a successful sale.

Before refreshing, hold any unfinished retail invoice or place the intended restaurant order while online. Mobile pull-to-refresh reloads the browser and clears unsaved cart work; it is not just a harmless price refresh.

If checkout was sent but the result is unclear

  1. Do not take payment or create the same sale again.
  2. Check Sales History, the saved draft or the Checkout queue, as appropriate.
  3. For an integrated payment, check the existing provider transaction.
  4. Record the invoice/order/payment references and ask a supervisor to review an unresolved result.

Closing a dialog is not a refund. A provider-paid transaction can need reconciliation even when the invoice did not finish.

Background invoice submission

When the profile's Enable Background Invoice Submission is enabled, eligible Sales Invoice sales can be accepted with stock reserved while submission finishes afterward. This requires stock reservation; when the required setup is absent, the application uses direct submission instead.

A queued message is not the same as a submitted invoice. Open Sales History → Checkout Queue to review reserved sales needing processing or operator review:

State What to do
Queued Wait for the accepted sale to be processed; do not recreate it.
Processing Allow the current attempt to finish.
Failed Read the error, correct its cause and use the available retry action if appropriate.
Requires Review Ask an authorised supervisor to inspect the document and reservation/payment result before retrying.

Background submission is not a separate offline-sales system and is not a promise that Sales Orders, POS Invoices and restaurant bills all use this same route.

Retry safely

Fix the actual cause: unavailable stock, missing account, invalid tracked stock or approval restrictions. Use the saved transaction's retry action rather than rebuilding a new cart with another payment.

Unresolved submissions can prevent Close Shift. Once the invoice is submitted, confirm the final status in Sales History.
